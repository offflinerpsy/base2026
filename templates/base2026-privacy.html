Privacy notice

Project forms, kept separate from public research.

Base2026 collects the information you choose to submit through the Support and Partner forms so the project can evaluate and respond to proposals.

What is collected

The forms may collect your name, work email, organization, role, proposal details, public URLs, timing, constraints and acknowledgment preference. Do not send passwords, credentials, private datasets, financial account details or confidential information.

How it is used

Submission data is used only for project operations: reviewing the proposal, contacting you and tracking a possible collaboration. It is not inserted into the public Base2026 search index, public datasets or source pages.

Storage and retention

Form submissions are stored in a separate private database operated through Cloudflare. Base2026 does not intentionally store your IP address or browser user-agent with the submission. Proposals are retained for up to 90 days unless an active conversation requires longer retention, after which they are deleted or reduced to non-personal operational notes.

Public tool activation measurement

When enabled, the three public tools may send a same-origin, first-party activation event so the project can understand whether an Evidence Search, Source Diversity Check, or Source-backed Brief workflow is being used. The measurement records only an allowlisted event name, one of the exact routes /tools/evidence-search/, /tools/source-diversity-check/, or /tools/source-backed-brief/, a server-generated UTC hour bucket and coarse allowlisted properties such as a count or response bucket. It does not claim unique visitors; the resulting counts are best-effort product signals, not proof of human actions.

Controlled links may optionally carry the fixed tags b26_campaign (one of none, evidence_pulse, worked_example, or agent_workflow) and b26_qa=1. These are self-declared cohort/campaign labels for experiment analysis and operator QA, not identity signals. A named campaign maps to experiment, b26_campaign=none leaves the event unattributed, a valid QA tag maps to operator_qa, and untagged events are unattributed/none. Duplicate or unknown values do not produce that dimension. The labels do not prove a human, unique visitor, returning visitor, or all traffic.

The measurement does not store raw URLs or query parameters, raw queries, record or source IDs, notes, IP addresses, browser user-agent strings or referrers. The browser reads only the fixed tags and propagates valid labels on same-origin navigation among those three routes; it never sends the complete URL or raw tag string as an event field. It does not use cookies, local storage, session storage or fingerprinting, and it is not connected to authentication, member research or the private acquisition pipeline. An IP address may be used transiently by Cloudflare's edge rate limiter to bound abuse; it is not written to the measurement point or an application database. If enabled, aggregate points use Cloudflare Analytics Engine's current three-month retention window and are not a visitor profile.

WordPress Evidence Sidebar

The plugin sends a topic only after an editor clicks Search: the browser sends the entered topic and a WordPress REST security nonce to that WordPress installation, then its server sends the topic to Base2026's public Evidence Brief API. The plugin does not automatically read or send the article body; selected-block text is included only if the editor explicitly copies it into the topic field and then searches. Version 0.1.1 uses a neutral plugin User-Agent instead of a WordPress version or client-site URL (version 0.1.0 uses the WordPress default, which can include both); the WordPress server's IP address and ordinary request metadata are visible to Base2026 and its hosting provider, Cloudflare. This plugin does not forward WordPress credentials, REST nonces or post IDs to Base2026. The plugin adds no persistent query store or separate analytics request, and the API handler reads the public corpus without writing a query record to an application database. API responses permit short-lived caching; that is separate from operational logs. Cloudflare operational-metadata logging and retention for these requests have not yet been verified, so no zero-logging or deletion-period guarantee is made. Do not enter confidential information. Contact hello@base2026.dev for privacy questions or a correction/deletion request. The form-retention and website-activation rules above do not establish the retention of plugin API requests.

Your choices

You may ask for correction or deletion through the Support form; mention “privacy request” in the proposal. Public acknowledgment is optional and is discussed before publication.

Service providers

Cloudflare provides hosting, request processing, rate limiting and database/measurement infrastructure. External links, including GitHub and X, have their own privacy practices.
